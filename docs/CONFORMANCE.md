Generated by hand this pass for the functions verified so far; full
auto-generation from the oracle test run (`function, oracle and version,
cases, max abs/rel error, status`) is planned but not yet wired up — see
`docs/VERIFICATION_PLAN.md`, Workstream A. edgelab reads these statuses
directly, so this file — not test output — is the source of truth for
"is quantcore proven to match the standard" until that automation exists.

`non-standard` (computes a real but non-default definition; documented),
`defect` (known wrong; do not use until fixed), `unverifiable` (no oracle
